# ORCD (MIT Engaging) training environment

`~/dyngrasp_rl/dyngrasp_rl.sif`: python:3.12.16-bookworm + venv `/opt/venv` from `requirements.lock` (Drake 1.57, jax[cuda12] 0.11.2, sbx 0.28, CPU-only torch). Tested on L40S, L4, A100, H100, H200 and RTX Pro 6000; `train_preempt.sbatch` excludes the B200/B300 nodes (cuBLAS 12.9 data-corruption warning there). The repo is not in the image: it lives in `~/dyngrasp_rl/repo`, and the job scripts put it on `PYTHONPATH`.

- Sync the repo (Mac, repo root): `rsync -az --delete --exclude={.venv,results,runs,__pycache__,.pytest_cache,.ruff_cache,.claude,.DS_Store} ./ orcd:dyngrasp_rl/repo/`
- Rebuild the image (apptainer `--fakeroot`, ~5 min): `cd ~/dyngrasp_rl/repo/scripts/orcd && sbatch build_image.sbatch`. After changing deps, regenerate the lock with `pip freeze --exclude-editable` inside the image.
- One-time setup (any account: the job scripts log to `/home/%u/dyngrasp_rl/...`, i.e. your own home): `mkdir -p ~/dyngrasp_rl/{runs,rl2,rl3}/.slurm && ln -sf ~/dyngrasp_rl/repo/scripts/orcd/train_*.sbatch ~/dyngrasp_rl/`
- Submit on L40S (16 CPUs, 6 h): `sbatch ~/dyngrasp_rl/train_normal.sbatch RUN [SEED] [N_ENVS] [KEY=VALUE ...]`
- Submit on preemptable (any GPU, 66 CPUs, 1 day, requeued on preemption): `sbatch [-c 32] ~/dyngrasp_rl/train_preempt.sbatch RUN ...`
- Outputs go to `~/dyngrasp_rl/runs/RUN/`. Resubmitting the same RUN resumes it. SIGUSR1 arrives 10 min before the time limit.
- Docker copy of the same environment (public, no repo code): `apptainer pull dyngrasp_rl.sif docker://victoriano012/dyngrasp-rl:<tag>`. To rebuild it on the Mac: `docker buildx build --platform linux/amd64 -t victoriano012/dyngrasp-rl:<date> .`
- Behaviour cloning (D) (any command, CPU or GPU): `scripts/orcd/run.sbatch`, examples in its header: demonstrations (`make_bc_demos.py generate`, then `merge`), training (`train_bc.py`, on a GPU), evaluation (`eval_rl.py`, then `compare_rl.py`). Training and both evaluations as one preemptable job: `CODE_DIR=<checkout> sbatch scripts/orcd/bc.sbatch RUN_DIR DATASET [KEY=VALUE ...]` (resumes by skipping finished steps).
- RL fine-tuning of a BC policy (D): `CODE_DIR=<checkout> sbatch -c 36 --gres=gpu:a100:1 scripts/orcd/ft.sbatch PLAN` runs one `finetune_rl.py` per plan line (`RUN KEY=VALUE ...`) on a shared GPU, with runs in `~/dyngrasp_rl/rl2/RUN/`; environments come from CPU jobs `sbatch -c 50 scripts/orcd/env_workers.sbatch ~/dyngrasp_rl/rl2/RUN:48` (they connect to the learner and reconnect after preemption). Demonstrations for the batches: `make_rl_demos.py` (one job per `--part`). 30-scene evaluation of a policy directory: `sbatch scripts/orcd/eval30.sbatch POLICY_DIR OUT`.
- RL PPO from the BC policy: `CODE_DIR=<checkout> sbatch --gres=gpu:TYPE:1 scripts/orcd/ppo.sbatch PLAN` runs one learner (`ppo_rl.py`) per plan line (`RUN KEY=VALUE ...`), runs in `~/dyngrasp_rl/rl3/RUN/`; the environments are CPU jobs `sbatch -c 64 -o ~/dyngrasp_rl/rl3/.slurm/%x_%j.out scripts/orcd/env_workers.sbatch --recycle 50 --ppo ~/dyngrasp_rl/rl3/RUN_A:32 ~/dyngrasp_rl/rl3/RUN_B:32` (whole episodes with the run's latest policy, and DAgger takeovers; they reconnect after preemption and end when every run is DONE). L5 check of checkpoints: `scripts/bc_bigeval.py` in `run.sbatch`.
